## 建议先做这四项

| 顺序 | 当前缺口与依据 | 建议交付与验收 |
| --- | --- | --- |
| **P1 · 1 保存与恢复项目** | R 的源码、数据、字体、样式和历史保存在组件内存；图表工作台也没有项目保存入口。刷新会丢失尚未导出的会话。见 `web/src/rstudio/RStudio.tsx`、`web/src/charts/ChartStudio.tsx`。 | 先做用户主动下载/打开项目包，保存源码、实际数据与字体、编辑记录、依赖版本；重开后图形与对象位置一致。可选浏览器自动保存需明确开启和清除入口，导入后运行脚本仍由用户触发。 |
| **P1 · 2 一键导出可复现材料** | R 导出脚本仍需用户手动配齐数据与字体；Plotly / pyecharts 导出的是结果配置，原始数据处理过程不在导出 Python 中。见 `web/src/rstudio/client.ts`、`web/src/charts/model.ts`。 | 导出 ZIP：原脚本、编辑后的可运行结果、数据、用户选择附带的字体、依赖版本与运行说明。用干净环境重放，验证图形；界面明确显示哪些编辑进入脚本或重放记录。与项目保存共用同一份版本化数据结构。 |
| **P1 · 3 导出规格与预览一致** | Matplotlib PNG 固定宽 2400；Plotly 固定 1200×800，可能改变预览比例；R PNG 来自 PDF 的固定 2× 栅格化。见 `PlaygroundExport.tsx`、`charts/renderer.ts`、`rstudio/pdfPreview.ts`。 | 统一提供毫米尺寸、像素/DPI、保持比例与背景设置；按引擎逐步补矢量格式。验收包含不同尺寸、字体、透明背景、图例和导出文件。R 轮廓 PDF 与可编辑文字模式需分别说明，不能简单把轮廓称为文字。 |
| **P1 · 4 在线关键流程进入 CI** | `figweave-web.yml` 当前只跑 i18n、build、Vitest；真实运行测试在 `web/e2e/figweave-site.spec.ts`，未接入该独立站工作流。 | 把四引擎运行→编辑→撤销→下载接入独立站 CI，保留失败截图/trace；锁定并缓存运行时，以免临时下载故障掩盖产品回归。界面发版时重拍截图作为产物，人工验收后更新 README。 |

| **P2** | 首次加载、重试与阶段进度 | Python 核心已自托管，R 核心仍访问锁定的 `webr.r-wasm.org/v0.6.0/`。本次单客户端 Plotly 首次运行约 16.5 秒，随后 pyecharts 约 8.5 秒；共享缓存、单次样本，不能代表大陆用户。先测不同网络冷/热启动，再决定同版本同哈希自托管 webR；同时显示实际阶段、重试原因和取消入口。 |
| **P2** | R 批量编辑与复杂布局 | 可先做多选文字统一字体/字号、对齐与间距；再补多图例、分面、数学公式、自定义 grob 的对象匹配回归样例。拖动继续只改显示位置，不改实验数据。自定义字体应支持 regular/bold/italic 的明确映射。 |
